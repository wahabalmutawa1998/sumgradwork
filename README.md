# متابعة المدارس — SUM × TREND

نظام متابعة المدارس والدفعات: المهام، المطبوعات، المسؤولين، المدارس المحتملة، الطلبات، السجل، والإحصائيات.

موقع ثابت — ما يحتاج تنصيب ولا سيرفر ولا خطوة بناء. **للنشر على DigitalOcean راجع [`DEPLOY.md`](DEPLOY.md).**

---

## هيكلة الملفات — وش تعدّل ووش تترك

| الملف | وظيفته | يتبدّل مع التحديثات؟ |
|---|---|---|
| `src/` | **المصدر** — كود النظام مقسّم ملفات واضحة + بيانات المدارس (`seed.json`) | إي — هنا تعدّل النظام |
| `build.js` | يبني `app.js` و `app.css` و `assets.js` من المصدر (`npm run build`) | نادراً |
| `app.js` + `app.css` + `assets.js` | **مخرجات البناء** — لا تعدّلها يدوياً، تنكتب فوقها مع كل بناء | إي، تلقائياً |
| `index.html` | الهيكل اللي يربط الملفات ببعض | نادراً |
| `server.js` | السيرفر — يقدّم الموقع ويخزّن البيانات المشتركة | نادراً |
| `storage.js` | طبقة حفظ البيانات | ❌ **لا تعدّله أبداً** |
| `custom.css` | **تعديلاتك أنت** على الشكل والألوان | ❌ ملفك — ما يلمسه البناء ولا التحديث |
| `custom.js` | **إضافاتك أنت** من أكواد | ❌ ملفك — ما يلمسه البناء ولا التحديث |
| `HANDOFF.md` | المواصفة الفنية الكاملة للنظام (قواعد العمل، الصلاحيات…) | مرجع |

**طريقة تعديل النظام:** عدّل بملفات `src/` ← شغّل `npm run build` ← ادفع بـ `git push`. البناء يكتب فوق `app.js` و `app.css` و `assets.js` فقط — ولا يقرب `index.html` ولا `storage.js` ولا `custom.*` ولا `server.js`، والبيانات أصلاً بقاعدة البيانات فما تتأثر بشي.

ولأي تعديل شكلي سريع بدون بناء: `custom.css` ينزل بعد `app.css` فأي قاعدة فيه تتغلّب على الأصل، و`custom.js` ينفَّذ بعد النظام كامل.

## ليش التحديث ما يمسح البيانات؟

البيانات (المدارس، المهام، الطلبات، السجل، الأكواد…) **مو داخل ملفات الكود أصلاً** — محفوظة بقاعدة البيانات على السيرفر (وجلسة الدخول بمتصفح كل جهاز). يعني:

- تحديث `app.js` أو `app.css` أو حتى `index.html` → البيانات باقية مثل ما هي.
- نزّل **نسخة احتياطية** كل فترة من الإعدادات ← البيانات ← نزّل نسخة احتياطية (ملف JSON تقدر تستورده بأي وقت).

## ✅ البيانات مشتركة بين كل الفريق

النظام يشتغل على سيرفر (`server.js`): أي تعديل من أي موظف ينحفظ بالسيرفر مباشرة ويبين للجميع.

- الموظف يعدّل من جهازه → التعديل يوصل السيرفر ويشوفه الكل.
- لو أحد من الفريق سوّى تعديل وأنت فاتح الصفحة، يطلع لك تنبيه أسفل الشاشة: **«فيه تعديل جديد من الفريق — حدّث الصفحة»**.
- لو اثنين حاولوا يحفظون بنفس الوقت، النظام يرفض الحفظ الثاني بدل ما يمسح شغل الأول، ويطلب من الثاني يحدّث الصفحة ويعيد تعديله.
- جلسة الدخول (مين مسجّل دخول) تظل خاصة بكل جهاز — كل موظف يدخل بكوده.

لو فتحت النظام بدون سيرفر (مثلاً فتح `index.html` مباشرة)، يرجع تلقائياً للحفظ بالمتصفح مثل قبل — بس بدون مشاركة.

## الدخول

كود الأدمن الافتراضي بهذا الإصدار: `1234` — **غيّره من داخل النظام أول ما تدخل**، وحط كود لكل موظف وفعّله. الموظف يشوف كل شي ويعدّل، بس تعديله يوقف **معلّق** لين توافق عليه من تبويب **الطلبات**.

**الأكواد تنظّم مو تحمي.** تمنع الغلط والعبث العفوي بين الفريق، لكنها مو حاجز أمني حقيقي — أي أحد معه الرابط يشوف النظام.
